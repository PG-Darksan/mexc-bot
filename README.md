# MEXC USDT無期限先物 自動売買ツール

24時間出来高・ボリンジャーバンド・RSI・EMA を使って、行きすぎた銘柄を
1倍で叩くボットです。吹き上げをショート、叩き売られをロングで取ります。
Windows / Android のアプリと、Oracle Cloud などに常駐させるサーバーから
できています。

**注文は常に本番の取引所へ出します。** 試し打ち (紙トレード) の仕組みは
ありません。開始を押した時点から、条件が成立すれば実際に建玉を持ちます。

## 売買のしくみ (既定値)

**入る条件** — 以下をすべて満たしたときに建てます。ショートとロングは
同じ項目を持ち、値も左右そろえてあります (RSI のしきい値だけ向きが逆)。

| 条件 | ショート | ロング |
| --- | --- | --- |
| 24時間売買代金 | 5,000,000 USDT 以上 | 同左 (共通) |
| RSI(7) | 97 以上 | 3 以下 |
| 価格 | BB(20) の +4σ を上抜け | BB(20) の -4σ を下抜け |
| レバレッジ / 証拠金 | 1倍 / 10 USDT | 1倍 / 10 USDT |

**行きすぎたときの逆張り** — バンドから大きく離れると RSI は 0 や 100 に
張り付いて動かなくなり、上の条件では拾えません。そこで σ のバンドから
**20% 以上** (既定) 離れたときは、RSI を見ずに入ります。

| 条件 | ショート | ロング |
| --- | --- | --- |
| 価格 | +4σ から 20% 以上 **上** | -4σ から 20% 以上 **下** |
| RSI | 見ない | 見ない |

このときの利確は、EMA ではなく **バンドからの乖離率 × 利確の係数** だけ
戻した位置に置きます。バンドの 40% 外で入ったなら、バンドの 20% 外が目標です。
出来高・資金調達・利確幅の下限は通常どおり効きます。

**見送る条件** — その方向が資金調達を *支払う側* のときだけ効きます
(率がマイナスならショートが支払い、プラスならロングが支払います)。

| 条件 | 既定値 |
| --- | --- |
| 負担率 | 0.1% を超えたら見送り |
| 調達間隔 | 2時間未満なら見送り |

受け取る側なら、率が大きくても見送りません。

**同じ銘柄を重ねて持たない** — 取引所にその銘柄の建玉がある間は、
方向に関わらず新規注文を出しません。手で建てたものや、ボットの再起動前に
建てたものも含めて見ます。持っている建玉に対して出すのは利確 (決済) だけです。

**出る条件**

- 利確 … 検知した瞬間の EMA(5) を固定し、そこからの乖離率の **0.5 倍** の位置。
  価格が EMA より 8% 上で検知したら、EMA の 4% 上が目標です (ロングは上下が逆)。
  行きすぎで入ったときだけは、EMA ではなくバンドからの乖離が基準になります。
- 損切り … **なし** (既定)。方向ごとに有効化できます。

**判定のタイミング**

15分足・1時間足・4時間足・日足を同時に見ます。どの時間軸も **60秒ごと** に、
進行中の足を含めて毎回計算し直します。4時間足だからといって4時間に1回では
ありません。

指標は TradingView と同じ計算にしてあります (標準偏差は母標準偏差、
RSI は Wilder 平滑)。

## 構成

```
mexc/
├── packages/
│   ├── mexc_core/      売買ロジック本体 (純Dart。アプリとサーバーで共有)
│   └── mexc_server/    常駐サーバー (Oracle Cloud などに置く)
├── app/                Flutter アプリ (Windows / Android)
└── deploy/             サーバーのセットアップ用ファイル
```

同じ `mexc_core` が、アプリの中でも (ローカル実行) サーバーの上でも
(サーバー接続) そのまま動きます。

## 2つの動かし方

### ローカル実行 — サーバーなし

アプリの中でボットを直接動かします。設定タブの「動かし方」で
「ローカル実行」を選ぶだけです。

- サーバーを用意しなくてよい
- アプリを閉じると止まる
- APIキーは端末の暗号化領域 (Windows は資格情報マネージャー、
  Android は EncryptedSharedPreferences) に保存されます

**Android で常時稼働はできません。** Android 15 以降、バックグラウンド処理は
24時間のうち合計6時間までに制限されています。Android は「見る・操作する」
端末と考えて、常時稼働はサーバーかWindowsに任せてください。

### サーバー接続 — Oracle Cloud に常駐

サーバーでボットを動かし、アプリからは設定変更と監視だけを行います。
アプリを閉じてもボットは動き続けます。

手順は [deploy/README.md](deploy/README.md) を参照してください。

## 最初に動かすまで

```bash
# 依存を取得
cd packages/mexc_core && dart pub get
cd ../mexc_server   && dart pub get
cd ../../app        && flutter pub get

# テスト
cd ../packages/mexc_core && dart test

# Windows アプリを起動
cd ../../app && flutter run -d windows
```

起動したら、

1. 設定タブで API キーを入れ、証拠金・レバレッジ・方向 (ショート / ロング) を
   確かめます。**開始した時点から本番の注文が出ます。**
2. 右上の「開始」を押します。
3. しばらく待つと、シグナルタブに監視銘柄の評価が並びます。

まずは証拠金を小さくし、片方向だけ入れて様子を見るのが無難です。
方向を切るには、設定タブの「ショートとロング」でその側のスイッチを切ります。
API キーを入れずに開始すると、判定だけ行い注文は出しません。

## ビルドするときの注意

### Android

このフォルダーは「デスクトップ」という日本語を含むパスにあります。Gradle は
既定で非ASCIIパスを拒むため、`android/gradle.properties` に
`android.overridePathCheck=true` を入れてあります。この設定で
`flutter build apk --debug` は通ります。

**`--release` は日本語パスのままでは通りません。** release は AOT
コンパイル (gen_snapshot) を通りますが、これが非ASCIIパスの中間ファイルを
読めず、次のように落ちます。

```
Error: Unable to read file: ...\デスクトップ\mexc\app\.dart_tool\flutter_build\...\app.dill
Dart snapshot generator failed with exit code 255
```

release APK を作るときは、ASCII だけのパスへ写してからビルドしてください。

```bash
mkdir -p /c/tmp/mexc
git archive HEAD | tar -x -C /c/tmp/mexc

# gradlew 一式は .gitignore に入っているので、書き出したあとに写す。
cp app/android/gradlew app/android/gradlew.bat /c/tmp/mexc/app/android/
cp app/android/gradle/wrapper/gradle-wrapper.jar /c/tmp/mexc/app/android/gradle/wrapper/

cd /c/tmp/mexc/app && flutter build apk --release
# → build/app/outputs/flutter-apk/app-release.apk (全ABI入り 50MB 前後)
```

release APK は `android/app/build.gradle.kts` の設定どおり **debug 鍵で
署名** されます。サイドロードには足りますが、ストアに出すなら keystore を
用意して `signingConfig` を差し替えてください。

Windows 側のビルドとテストは日本語パスのままで問題ありません。

### Windows

`flutter_secure_storage` のビルドには Visual Studio Build Tools の
**C++ ATL** が必要です。入っていないとリンクで失敗します。

### 静的解析

`flutter analyze` は、この Dart SDK (3.11.0) では解析サーバーが
`Bad state: No definition of type double` で落ちます。SDK 側の不具合で、
ビルドとテストには影響しません。`packages/mexc_core` 単体の
`dart analyze` は正常に動きます。

## 監視銘柄数とサーバーの目安

既定の「24時間出来高 5M USDT 以上」だと、対象はおよそ 90〜100 銘柄です。
出来高フィルタを緩めて監視銘柄を増やす場合、必要なスペックは次のように変わります。

| 監視銘柄 | 系列数 (×4時間軸) | 判定1回 | CPU | メモリ |
| --- | --- | --- | --- | --- |
| 約95 (既定) | 380 | 約0.3〜0.6秒 | 数秒/分 | 約200MB |
| 1,000 | 4,000 | **約0.9秒** | **8.5秒/分** | **約400MB** |

どちらもデスクトップPCでの実測値 (定常状態)。CPU の大半は判定そのものでは
なく、WebSocket で流れてくる足データを捌く処理です。非力なサーバーでは
2〜3倍かかると見てください。

必要スペックの目安:

| 監視銘柄 | 目安 |
| --- | --- |
| 約95 (既定) | 1 vCPU / 1GB で余裕 |
| 1,000 | **2 vCPU / 2GB** を推奨 (1 vCPU / 1GB でも計算上は動くが余裕がない) |

**Google Cloud の無料枠 (e2-micro) はベースラインが 0.25 vCPU** で、1分あたりに
使える CPU が15秒ぶんしかありません。1,000銘柄では余裕がないので勧めません。
既定の 90〜100 銘柄なら問題なく動きます。Oracle の Always Free
(2 vCPU / 12GB) なら 1,000 銘柄でも余裕があります。

### 起動直後の待ち時間

ローソク足の履歴は REST で取るため、レート制限のぶんだけ時間がかかります。

| 系列数 | 全部揃うまで (実測) |
| --- | --- |
| 380 (約95銘柄) | 約3分 |
| 4,000 (1,000銘柄) | 約50分 |

揃った系列から順に判定へ回るので、全部揃うのを待つ必要はありません。
残り系列数はアプリの状況画面と `status.dart` で確認できます。
サーバーを再起動するたびにこの時間がかかる点は見込んでおいてください。

## サーバーの状態を端末から見る

```bash
cd packages/mexc_server
BOT_TOKEN=<トークン> dart run bin/status.dart --url ws://127.0.0.1:8080/ws
# -w を付けると更新を流し続けます
```

監視中の銘柄が RSI の高い順に並び、却下された理由まで出ます。

## 実発注に切り替える前に

- **MEXC のAPIキー** … 先物の発注権限が要ります。KYC の完了が前提です。
- **IPホワイトリスト** … 登録しないキーは **90日で自動失効** します。
  無人運用中に突然止まるので、サーバーの固定IPを登録してください。
- **手数料** … API経由の手数料は Web/アプリとは別体系で、Taker 0.08% 前後です。
  往復で 0.16% かかるため、利確幅がこれを下回ると必ず損をします。
  既定では「利確幅の下限 0.3%」で弾くようにしてあります。
- **損切りなしのリスク** … 1倍でも、価格が2倍になれば証拠金はほぼ全損します。
  実データを調べたところ、最悪の例では検知後に +28,000% 逆行した銘柄が
  ありました (資金調達間隔1時間の新規上場銘柄)。既定の資金調達フィルタは
  こうした銘柄を弾きますが、保険として損切りを入れることも検討してください
  (設定タブ → 利確と損切り)。

## 設定できること

設定タブですべて変えられます。項目ごとに畳んであり、「ショートとロング」だけ
開いた状態で始まります。主なもの:

- 出来高の下限 (M USDT 単位)、手動での銘柄指定・除外
  - 監視する銘柄数に上限はありません。出来高の下限だけで絞ります
- 時間軸の選択 (1分足〜週足)
- BB期間、RSI期間、EMA期間 (方向で共通)
- ショートとロングを左右に並べて、それぞれに:
  RSIのしきい値、σ倍率、レバレッジ、1回あたりの証拠金、指値の幅、
  利確の係数、利確幅の下限、行きすぎ逆張りの有無とその乖離幅、
  損切りの有無と幅、資金調達の負担率と間隔
  - 「ショートの値をロングへ」で、RSI のしきい値だけ 100 から引いた値にして
    まとめてそろえられます
- 成行/指値、ヘッジ/一方向、分離/クロス、利確を取引所に預けるか
- 判定間隔、同時保有数、再エントリーの待ち時間

## 動かしている間に見られるもの

画面は **状況 / ログ / 設定** の3つです。

- **状況** … 稼働状態・監視銘柄数・残高・累計損益・勝率に加えて、
  保有中の建玉と利確までの進み具合、いまの条件 (ショートとロングを左右に並べて)、
  直近の検知、決済済みの履歴を1枚にまとめてあります
- **ログ** … 検知・発注・エラーの記録。「なぜ入らなかったか」はここを見ます
- **設定** … 下の「設定できること」のとおり

## 技術的な注意

- REST の基底URLは `https://api.mexc.com` です (2026年1月に
  `contract.mexc.com` から移行)。WebSocket は `wss://contract.mexc.com/edge`
  のままなので、両者を混同しないでください。
- 発注は `POST /api/v1/private/order/create` です。ネット上の古いサンプルが
  使う `order/submit` は旧ドキュメントのパスです。
- 発注系のレート制限は 4回/2秒 と厳しいため、複数銘柄の同時発注は順番に行います。
