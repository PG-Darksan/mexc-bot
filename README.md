# MEXC USDT無期限先物 自動売買ツール

24時間出来高・ボリンジャーバンド・RSI・EMA を使って、行きすぎた銘柄を
1倍で叩くボットです。吹き上げをショート、叩き売られをロングで取ります。
Windows / Android のアプリと、Oracle Cloud などに常駐させるサーバーから
できています。

**注文は常に本番の取引所へ出します。** 試し打ち (紙トレード) の仕組みは
ありません。開始を押した時点から、条件が成立すれば実際に建玉を持ちます。

## 売買のしくみ (既定値)

手法は 2 つあり、**同時に動かせます** (同じ銘柄に両方から重ねて建てることは
しません)。

- **今までの手法** … BB の ±σ を抜けて RSI が振り切れたら逆張りで入り、EMA(5) へ
  戻る途中で利確します。損切りは置きません。下の表とこの節の説明はこちらの物です。
- **検証済みの手法** … 1 年分の検証で前半・後半とも黒字だった手法です。既定では
  切ってあります (下の「検証済みの手法」)。

**入る条件 (今までの手法)** — 以下をすべて満たしたときに建てます。ショートとロングは
同じ項目を持ち、値も左右そろえてあります (RSI のしきい値だけ向きが逆)。

| 条件 | ショート | ロング |
| --- | --- | --- |
| 24時間売買代金 | 5,000,000 USDT 以上 | 5,000,000 USDT 以上 |
| 時間軸 | 15分 / 1時間 / 4時間 / 日足 | 15分 / 1時間 / 4時間 / 日足 |
| RSI(7) | 97 以上 | 3 以下 |
| 価格 | BB(20) の +4σ を上抜け | BB(20) の -4σ を下抜け |
| レバレッジ / 証拠金 | 1倍 / 10 USDT | 1倍 / 10 USDT |

証拠金は、固定額 (USDT) の代わりに**資産の割合 (%) をスライダーで**決めることも
できます。資産は口座の USDT の合計 (建玉の証拠金や含み損益も含む) で、その銘柄で
持てる建玉の上限が資産より小さい時は、上限に対する割合にします (取引画面の「何 %」と
同じ。後で買い足せる余地を残すため)。使える残高を超える分は建てません。

出来高の下限・時間軸・指標の期間 (BB / RSI / EMA) も**ショートとロングで
別々に決められます**。既定は同じ値ですが、たとえば「ロングは出来高 20M 以上の
4時間足だけ、ショートは 5M 以上の 15分足も見る」といった分け方ができます。

**行きすぎたときの逆張り** — バンドから大きく離れると RSI は 0 や 100 に
張り付いて動かなくなり、上の条件では拾えません。そこで σ のバンドから
**20% 以上** (既定) 離れたときは、RSI を見ずに入ります。

| 条件 | ショート | ロング |
| --- | --- | --- |
| 価格 | +4σ から 20% 以上 **上** | -4σ から 20% 以上 **下** |
| RSI | 見ない | 見ない |

このときの利確は、EMA ではなく **バンドからの乖離率 × 利確の係数** だけ
戻した位置に置きます。バンドの 40% 外で入ったなら、バンドの 20% 外が目標です。
出来高・資金調達・利確幅の下限は通常どおり効きます。

**見送る条件** — その方向が資金調達を *支払う側* のときだけ効きます
(率がマイナスならショートが支払い、プラスならロングが支払います)。

| 条件 | 既定値 |
| --- | --- |
| 負担率 | 0.1% を超えたら見送り |
| 調達間隔 | 2時間未満なら見送り |

受け取る側なら、率が大きくても見送りません。

**同じ銘柄を重ねて持たない** — 取引所にその銘柄の建玉がある間は、
方向に関わらず新規注文を出しません。同じ向きに何度も積み増すことも、
反対向きを被せることもしません。手で建てたものや、ボットの再起動前に
建てたものも含めて見ます。持っている建玉に対して出すのは利確 (決済) だけです。

同時に持てる件数に上限は設けていません。銘柄ごとに1つまで、というのが
唯一の縛りです。

**建玉モードは一方向のみ** — 同じ銘柄に反対向きを同時に持つことがないので、
ヘッジモードは使いません。**MEXC 側も「一方向モード」にしてください。**
食い違うと決済注文が通らず、起動時に警告が出ます。

**買い足し / 売り足し (任意)** — 設定で入れると、成行で建てた直後に、
口座に残っている USDT の指定した割合を証拠金にして、**証拠金に対する含み損が
指定の % になる価格**へ同じ向きの指値を置きます (ロングは建値の下に買い、
ショートは建値の上に売り。レバレッジ 1 倍なら建値からの値動き % と同じ)。
約定すると平均建値が有利な側に寄ります。利確の目標は動かさず、枚数だけ
全建玉ぶんに置き直します。決済したら残っている指値は取り消します
(取引所側で利確された場合は、次の判定までの間だけ残ることがあります)。
指値を置いた分の資金は凍結されるので、100% にすると次の銘柄に回す資金が
無くなります。既定では切ってあります。

**出る条件**

- 利確 … 検知した瞬間の EMA(5) を固定し、そこからの乖離率の **0.5 倍** の位置。
  価格が EMA より 8% 上で検知したら、EMA の 4% 上が目標です (ロングは上下が逆)。
  行きすぎで入ったときだけは、EMA ではなくバンドからの乖離が基準になります。
- 損切り … 既定では**置きません** (1倍なので追証は出ません)。
  建てたあとに、チャートタブから手で入れることはできます。

**検証済みの手法 (任意)** — 設定タブの「検証済みの手法」で「この手法を使う」を
入れると、今までの手法と同時に動きます。中身は次の通りです (どれも変えられます。
「検証した値に戻す」で元の値に戻ります)。

| 項目 | 既定値 |
| --- | --- |
| 向き | ロングだけ |
| 入る条件 | 15分足で BB(20) の -4σ を下抜け、RSI(7) が 5 以下 (24時間売買代金 1M USDT 以上) |
| 利確 / 損切り | 入値 +3σ / 入値 -3σ (σ は検知した瞬間の BB の 1σ)。どちらも発注と同時に取引所へ預ける |
| 最長保有 | 12 時間。過ぎたらボットが成行で閉じる (ボットを止めている間は閉じない) |
| 同時に持つ数 | この手法で建てた物だけで 10 件まで |
| 証拠金 | 資産の 5% (今までの手法とは別に決める) |

買い足しと、RSI を待たない「行きすぎ」の入り方は使いません (検証していないため)。
検証の中身は [research/report.md](research/report.md) の 5.2 節にあります。
今までの手法の買い足しに残り資金の 100% を使う設定だと、建てた後は資金が凍結される
ので、検証済みの手法に回す資金も無くなります。両方使う時は買い足しの割合を下げるか、
買い足しを切って下さい。

**判定のタイミング**

15分足・1時間足・4時間足・日足を同時に見ます。どの時間軸も **60秒ごと** に、
進行中の足を含めて毎回計算し直します。4時間足だからといって4時間に1回では
ありません。

指標は TradingView と同じ計算にしてあります (標準偏差は母標準偏差、
RSI は Wilder 平滑)。

## 構成

```
mexc/
├── packages/
│   ├── mexc_core/      売買ロジック本体 (純Dart。アプリとサーバーで共有)
│   └── mexc_server/    常駐サーバー (Oracle Cloud などに置く)
├── app/                Flutter アプリ (Windows / Android)
└── deploy/             サーバーのセットアップ用ファイル
```

ボットはサーバーの上で動き、アプリはサーバーにつないで見る・操作するだけです。

## 動かし方 — サーバーに常駐

ボットはサーバー (ConoHa VPS や Oracle Cloud) で動かします。アプリからは
設定の変更と監視だけを行い、アプリを閉じてもボットは動き続けます。
「開始」を押すと「停止」を押すまで動き、サーバーが立ち上がり直しても
最後に押した状態を引き継ぎます。

取引所の API キーはサーバーの `/etc/mexc-bot/env` にだけ置きます。
残高・建玉 (手で建てたものも)・決済の記録も、サーバーが取引所から取って
アプリへ返すので、端末に鍵は要りません。

以前の版にあった「ローカル実行 (アプリの中でボットを動かす)」はなくしました。

手順は [deploy/README.md](deploy/README.md) を参照してください。

## 最初に動かすまで

```bash
# 依存を取得
cd packages/mexc_core && dart pub get
cd ../mexc_server   && dart pub get
cd ../../app        && flutter pub get

# テスト
cd ../packages/mexc_core && dart test

# Windows アプリを起動
cd ../../app && flutter run -d windows
```

起動したら、

1. 設定タブの「サーバーへの接続」に URL と接続トークンを入れ、証拠金・
   レバレッジ・方向 (ショート / ロング) を確かめます。
   **開始した時点から本番の注文が出ます。**
2. 右上の「開始」を押します。
3. しばらく待つと、シグナルタブに監視銘柄の評価が並びます。

まずは証拠金を小さくし、片方向だけ入れて様子を見るのが無難です。
方向を切るには、設定タブの「ショートとロング」でその側のスイッチを切ります。
サーバーに API キーを入れずに開始すると、判定だけ行い注文は出しません。

## ビルドするときの注意

### Android

このフォルダーは「デスクトップ」という日本語を含むパスにあります。Gradle は
既定で非ASCIIパスを拒むため、`android/gradle.properties` に
`android.overridePathCheck=true` を入れてあります。この設定で
`flutter build apk --debug` は通ります。

**`--release` は日本語パスのままでは通りません。** release は AOT
コンパイル (gen_snapshot) を通りますが、これが非ASCIIパスの中間ファイルを
読めず、次のように落ちます。

```
Error: Unable to read file: ...\デスクトップ\mexc\app\.dart_tool\flutter_build\...\app.dill
Dart snapshot generator failed with exit code 255
```

release APK を作るときは、ASCII だけのパスへ写してからビルドしてください。

```bash
mkdir -p /c/tmp/mexc
git archive HEAD | tar -x -C /c/tmp/mexc

# gradlew 一式は .gitignore に入っているので、書き出したあとに写す。
cp app/android/gradlew app/android/gradlew.bat /c/tmp/mexc/app/android/
cp app/android/gradle/wrapper/gradle-wrapper.jar /c/tmp/mexc/app/android/gradle/wrapper/

cd /c/tmp/mexc/app && flutter build apk --release
# → build/app/outputs/flutter-apk/app-release.apk (全ABI入り 50MB 前後)
```

release APK は `android/app/build.gradle.kts` の設定どおり **debug 鍵で
署名** されます。サイドロードには足りますが、ストアに出すなら keystore を
用意して `signingConfig` を差し替えてください。

Windows の **release も同じ理由で日本語パスでは通りません** (`app.dill` を
読めずに gen_snapshot が落ちます)。`flutter run -d windows` と
`flutter test` は日本語パスのままで動きます。release をビルドするときは、
Android と同じように ASCII のパスへ写してください。

```bash
rm -rf /c/tmp/mexc-win && mkdir -p /c/tmp/mexc-win
git ls-files -c -o --exclude-standard -z | tar --null -T - -cf - \
  | tar -xf - -C /c/tmp/mexc-win

cd /c/tmp/mexc-win/app && flutter build windows --release
# → build/windows/x64/runner/Release/ (フォルダーごと配ります)
```

### Windows

`flutter_secure_storage` のビルドには Visual Studio Build Tools の
**C++ ATL** が必要です。入っていないとリンクで失敗します。

### 静的解析

`flutter analyze` は、この Dart SDK (3.11.0) では解析サーバーが
`Bad state: No definition of type double` で落ちます。SDK 側の不具合で、
ビルドとテストには影響しません。`packages/mexc_core` 単体の
`dart analyze` は正常に動きます。

## 監視銘柄数とサーバーの目安

既定の「24時間出来高 5M USDT 以上」だと、対象はおよそ 90〜100 銘柄です。
出来高フィルタを緩めて監視銘柄を増やす場合、必要なスペックは次のように変わります。

| 監視銘柄 | 系列数 (×4時間軸) | 判定1回 | CPU | メモリ |
| --- | --- | --- | --- | --- |
| 約95 (既定) | 380 | 約0.3〜0.6秒 | 数秒/分 | 約200MB |
| 1,000 | 4,000 | **約0.9秒** | **8.5秒/分** | **約400MB** |

どちらもデスクトップPCでの実測値 (定常状態)。CPU の大半は判定そのものでは
なく、WebSocket で流れてくる足データを捌く処理です。非力なサーバーでは
2〜3倍かかると見てください。

必要スペックの目安:

| 監視銘柄 | 目安 |
| --- | --- |
| 約95 (既定) | 1 vCPU / 1GB で余裕 |
| 1,000 | **2 vCPU / 2GB** を推奨 (1 vCPU / 1GB でも計算上は動くが余裕がない) |

**Google Cloud の無料枠 (e2-micro) はベースラインが 0.25 vCPU** で、1分あたりに
使える CPU が15秒ぶんしかありません。1,000銘柄では余裕がないので勧めません。
既定の 90〜100 銘柄なら問題なく動きます。Oracle の Always Free
(2 vCPU / 12GB) なら 1,000 銘柄でも余裕があります。

### 起動直後の待ち時間

ローソク足の履歴は REST で取るため、レート制限のぶんだけ時間がかかります。

| 系列数 | 全部揃うまで (実測) |
| --- | --- |
| 380 (約95銘柄) | 約3分 |
| 4,000 (1,000銘柄) | 約50分 |

揃った系列から順に判定へ回るので、全部揃うのを待つ必要はありません。
残り系列数はアプリの状況画面と `status.dart` で確認できます。
サーバーを再起動するたびにこの時間がかかる点は見込んでおいてください。

## 実発注に切り替える前に

- **MEXC のAPIキー** … 先物の発注権限が要ります。KYC の完了が前提です。
- **IPホワイトリスト** … 登録しないキーは **90日で自動失効** します。
  無人運用中に突然止まるので、サーバーの固定IPを登録してください。
- **手数料** … API経由の手数料は Web/アプリとは別体系で、Taker 0.08% 前後です。
  往復で 0.16% かかるため、利確幅がこれを下回ると必ず損をします。
  既定では「利確幅の下限 0.3%」で弾くようにしてあります。
- **損切りなしのリスク** … 1倍でも、価格が2倍になれば証拠金はほぼ全損します。
  実データを調べたところ、最悪の例では検知後に +28,000% 逆行した銘柄が
  ありました (資金調達間隔1時間の新規上場銘柄)。既定の資金調達フィルタは
  こうした銘柄は弾きますが、損切りは既定で置かないので、1回あたりの証拠金を
  小さくして備えてください。必要ならチャートタブから損切りを入れられます。
  検証済みの手法は、損切りも発注と同時に取引所へ預けます。
- **検証の中身** … 検証済みの手法を選んだ検証も、黒字にできなかった手法の検証も、
  [research/report.md](research/report.md) の 1 つにまとめてあります。

## 設定できること

設定タブですべて変えられます。手法ごとに分けて並べてあります。主なもの:

- **今までの手法** (EMA の戻りで利確)
  - この向きで建てるか・24h出来高の下限 (M USDT 単位)・RSI のしきい値は、
    ショートとロングで別々に決められます
    - 見る銘柄は出来高の下限だけで決まります。銘柄数に上限は無く、
      手で選んだり外したりもしません
  - 判定に使う時間足、σ倍率、保持する足、レバレッジ
  - 1回あたりの証拠金 (固定額か、資産の割合をスライダーで)
  - 利確の係数、利確幅の下限、最長保有時間 (過ぎたら成行で決済。0 で使わない)、
    行きすぎ逆張りの有無とその乖離幅、資金調達の負担率と支払いまでの時間
  - 買い足し / 売り足しの有無、指値を置く含み損 (%)、残り資金のうち使う割合 (%)
- **検証済みの手法** (σ で利確と損切り): 使うか、時間足、σ倍率、RSI のしきい値、
  利確と損切りの σ、最長保有時間、同時に持つ数、24h出来高の下限、レバレッジ、
  1回あたりの証拠金 (固定額か、資産の割合をスライダーで)
- 判定間隔、再エントリーの待ち時間、同時に持つ建玉の上限 (どちらの手法の物も
  手で建てた物も数える。0 なら上限なし)
- サーバーへの接続 (URL と接続トークン)
  - サーバー接続では「接続を試す」で、URL とトークンのどちらが悪いのかを
    その場で切り分けられます

次のものは切り替えられません。**常にこの動きで固定**です。

| 項目 | 固定の動き |
| --- | --- |
| 新規建て | 成行 (指値は使わない) |
| マージン | 分離 (クロスは使わない) |
| 建玉モード | 一方向 (MEXC 側も一方向にしてください) |
| 利確 (と損切り) | 発注と同時に取引所へ預ける |
| 資金調達率のフィルタ | 常に効く (負担率と間隔の基準だけ方向ごとに決める) |

## 動かしている間に見られるもの

画面は **ホーム / 銘柄 / 履歴 / 設定** の4つです。
右上のボタンで、明るい表示と暗い表示を切り替えられます。

- **銘柄** … 取引できる全銘柄を、24h出来高の下限 (既定 1M USDT、
  3M / 5M / 10M / 30M / 50M / 100M に変えられる) で絞り、**上昇率 / 下落率 /
  値幅 / 出来高** で並べ替えられます。名前でも探せます。
  **行を押すと、その行のすぐ下にチャートが開きます** (時間軸は 5m / 15m /
  1h / 4h / 1D。もう一度押すか × で閉じます)。保有中の銘柄なら建値・利確・
  買い足しの位置も引きます。利確ラインを動かすときは、そこから
  「ホームで利確を動かす」でホームのチャートへ移れます。
  保有中の銘柄には印が付きます。一覧は 1 分ごとに取り直します。

- **ホーム** … 上から順に、口座 (利用可能なUSDT・建玉に使っているUSDT・
  現在の含み損益)、チャート、恐怖指数、成績 (記録にある決済の回数・累計損益・
  勝率)、稼働状況、売買の条件、最近の検知。
  チャートは銘柄を名前で探せて、保有している銘柄と BTC/USDT はボタンで
  切り替えられます。ボリンジャーバンドと EMA を重ねたローソク足で、時間軸は
  5m / 15m / 1h / 4h / 1D。保有中の銘柄では、**利確と損切りのラインをその場で
  動かして取引所へ送れます** (チャートを上下になぞるか、スライダーで)。
  **残高は端末が直接取りに行くので、ボットを止めていても「更新」を押せば
  すぐ出ます** (サーバー接続でも、アプリにAPIキーを入れてあれば同じです)
- **履歴** … 保有中 / 決済済み / ログの3つ。決済済みの記録は1件ずつ、
  またはまとめて消せます
- **設定** … 下の「設定できること」のとおり

チャートに出すデータは、**端末が取引所と alternative.me の公開APIから直接**
取ります。サーバー接続モードでも同じで、サーバーは売買だけを受け持ちます。

### 手で注文する (取引画面)

ホームのチャートの「取引画面で開く」(保有中の建玉の下にもあります) で、
全画面のチャートと注文欄が開きます。

- **チャート** … 2 本指でつまむと拡大・縮小、1 本指でなぞると過去へ動きます
  (パソコンはホイールとドラッグ)。上の「○○ 本」で描く本数を選べます
  (ホームのチャートの本数も同じ値を覚えます)。時間軸は 1m / 5m / 15m / 1h /
  4h / 1D。
- **線を引く** … 上の道具で、横線 (タップ)・2 点を結ぶ線 (2 回タップ)・
  消す (線をタップ)・色・全部消す。線は銘柄ごとに端末に残ります。
- **注文** … 買い / 売りと、成行 / 指値 / 条件付き (トリガー注文) を選びます。
  値段の欄の横のボタンを押してからチャートをタップするか、チャートを
  長押しして出る選択肢 (指値で買う・この値段になったら売る・利確をここに …)
  で値段が入ります。
- **数量** … 証拠金 (USDT) を入れるか、スライダーと 10 / 25 / 50 / 75 / 100% の
  ボタンで「使える残高の何 %」かを選びます。レバレッジも選べます。
  ただし、**その銘柄で持てる建玉の上限 (証拠金に直した額) が使える残高より小さい時は、
  上限の何 %** になります (例: 残高 800 USDT・上限 200 USDT の銘柄で 25% → 50 USDT)。
  残高を基準にすると上限いっぱいで建ってしまい、後からナンピンできなくなるためです。
  決まる額は、使える残高と、その銘柄の残り (上限から、持っている建玉と出ている注文を
  引いた分) を超えません。超える額を入れると、注文欄に出ます。
- **利確 / 損切り** … 成行と指値は発注と同時に取引所へ預けます。条件付き注文
  には取引所が利確 / 損切りを付けられないので、**発動して建玉ができたら
  サーバーが置きます** (予約はサーバーを再起動しても残ります)。
- 建玉 (手で建てたものも) の利確 / 損切りの変更と成行決済、出ている注文
  (ボットの買い足しも) の取り消しも、この画面からできます。
- 手で注文を出している銘柄には、ボットは新しく入りません (約定すると
  ひとつの建玉にまとまるため)。

注文はサーバーが取引所へ出すので、サーバーにつながっている時だけ出せます。

### アプリのロック

右上の鍵のボタンで、15 分〜8 時間・明日の朝まで・時刻を決めて、アプリを
ロックできます。ロックの間はチャートも値段も見えません (売買の通知は届きます)。
急ぎのときは、ロック画面のボタンを 10 秒押し続けると開きます。

## 技術的な注意

- REST の基底URLは `https://api.mexc.com` です (2026年1月に
  `contract.mexc.com` から移行)。WebSocket は `wss://contract.mexc.com/edge`
  のままなので、両者を混同しないでください。
- 発注は `POST /api/v1/private/order/create` です。ネット上の古いサンプルが
  使う `order/submit` は旧ドキュメントのパスです。
- 発注系のレート制限は 4回/2秒 と厳しいため、複数銘柄の同時発注は順番に行います。
